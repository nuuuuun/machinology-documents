# Engineering ロードマップ

## 方針
Engineeringは、**AIに任せやすい実装知識より、AIだけでは完結しにくい判断・本番作業・検証能力を先に身につける**。

AIはコード生成、調査、設定例、テスト案、ドキュメント作成には非常に強い。一方で、顧客固有の制約を踏まえた最終判断、本番環境の状態確認、事故時の責任ある判断、実機・審査・権限を伴う操作は人間側の理解が重要になる。

> AIの能力は利用できるツール・権限・対象サービスへのアクセス状況で変わる。ここでは「AIに相談できる」ではなく、**Machinologyの案件でAIに大部分を委ねても安全か**を基準に分類する。

## AI代替度の分類
- 🔴 **人間優先**：AIでは大体できない、またはAI任せのリスクが高い。最優先で自分が理解・判断できるようにする。
- 🟡 **AI協働**：AIが案・コード・手順をかなり作れるが、人間の設計判断・検証が必要。
- 🟢 **AI委任寄り**：AIに大部分を任せやすい。仕組みを理解し、生成物をレビューできればよい。

## AIに任せてよいものを後回しにする
次の領域は「知らなくてよい」わけではないが、**暗記・手書き実装の優先度は低い**。

- HTML/CSS/JavaScriptの細かな文法
- Flutter Widgetの個別API
- Gitコマンドの暗記
- GitHub Actions YAMLの細かな記法
- Firebase CRUDコード
- REST API呼び出しの定型コード
- Excel関数の暗記
- WordPressの軽微なCSS/PHP修正
- AI API / Promptの定型実装
- ストア説明文やドキュメントの初稿作成

これらは **「AIが出したものを読んで、危険かどうか判断できる最低限の基礎」** を持てばよい。

## Machinologyで目指すEngineering能力
最終的なゴールは、すべてのコードを自分で書けることではない。

**「AIに実装を任せても、設計・セキュリティ・本番・障害・顧客影響について自分が責任を持って判断できるエンジニア」** を目指す。
